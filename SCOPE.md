# Research scope and boundaries

## In scope

- Publicly observable screens, navigation, information architecture, interaction patterns, responsive layout, accessibility, validation, and user-visible states.
- App behaviour observed on a device and account the researcher is authorized to use.
- Static inspection of an APK that the researcher is legally authorized to examine, within applicable licence terms.
- Passive observation of permitted website/browser behaviour and ordinary network metadata, without bypassing app protections or access controls.
- Clean-room functional specifications and independently created NIGHTLIFEZ designs and code.

## Out of scope

- Copying District source code, proprietary images, icons, branding, exact visual assets, or protected text.
- Circumventing DRM, certificate pinning, authentication, bot protection, licensing controls, or other technical protections.
- Accessing private APIs, other users' data, private account areas, or data outside the researcher's authorization.
- Replaying private endpoints or automating purchases/payments against District.
- Capturing, committing, or sharing passwords, OTPs, session cookies, auth tokens, UPI PINs, payment data, or personal information.
- Using research outputs as proof of District's internal implementation when only UI behaviour has been observed.

## Output standard

Produce a behavioural map, not a code clone. Each feature specification must identify:
- What the user sees and can do.
- Preconditions and entry points.
- States and transitions.
- Validation and error behaviour.
- Responsive/accessibility behaviour.
- Observed evidence.
- Unknowns and assumptions.
- An original NIGHTLIFEZ implementation proposal.
